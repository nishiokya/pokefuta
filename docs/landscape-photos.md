# 周辺の風景を投稿する

投稿時に「周辺の風景」を選べるようにする。K11による自動分類、過去写真の一括分類、自由入力タグや専用ギャラリーは追加しない。

## 投稿と表示

- 写真ごとの `photo.is_landscape`（boolean、NOT NULL、既定false）に自己申告を保存する。
- `/api/image-upload` は省略・`false`を通常写真、`true`を周辺風景とする。それ以外は400。既存クライアントの投稿も継続できる。
- 写真を選び直すとチェックを外す。送信中・送信済みは分類を変更できない。
- GPS必須・蓋から50m以内・既存の対象マッチングを維持する。風景には蓋が写っていなくてもよいが、遠方の観光写真は対象外。
- 投稿一覧、蓋の詳細、公開訪問カード、写真単体ページで風景と分かるラベルを付ける。
- 代表写真は風景以外から選ぶ。自分の写真優先・コメント優先・品質採点よりも風景除外を優先する。風景しかない場合は蓋の写真を募集中と表示し、風景は一覧から開ける。
- 風景だけを投稿した利用者は訪問済み・スタンプ取得済みだが、「蓋写真コンプリート」とは表示しない。蓋写真の登録状態とは文言を分ける。
- 新しいGA4ディメンションやイベントは追加せず、既存の投稿ファネルを維持する。

## 集計と採点

`get_site_counts().posts / public_posts` は風景を含む投稿数。`manholes_with_photos` と `get_public_prefecture_completion().with_photo` は公開訪問に属する風景以外の写真だけを数える。非公開化すると充足率から外れる。

品質採点の `quality_*` と `is_landscape` は独立させる。K11の採点ロールや処理は変更しない。未選択・既存写真のfalseは「蓋をAI等で検証した」という意味ではない。

公開訪問カードの既存ビューには `latest_photo_is_landscape` を追加する。公開範囲を決める `public_user_visit_base` は変更せず、内部認証ID・EXIF等の公開列は増やさない。同一訪問に両方あるときは蓋を優先し、風景だけの場合はラベル付きで表示する。

投稿フィードと写真単体共有は投稿そのものを見せるため、風景もラベル付きで表示する。一方、蓋詳細の代表画像・蓋OGP・スタンプ帳OGPのコラージュは場所や収集状況の代表なので風景を除外する。

## 訪問記録

風景を投稿した場合も通常と同じ訪問記録・スタンプを付与する。GPS必須・蓋から50m以内の条件も同じである。風景投稿だけを訪問付与から分離する処理は追加しない。

## 図鑑との導入順序

写真館は図鑑の `docs/api/manholes.json` にある写真充足情報も使う。片方だけで公開しない。

1. `20260929100000_photo_landscape.sql` をDBへ適用する。新列を読むコードの公開より先に行う。既存写真はfalseなので既存の動作は維持される。
2. `pokefuta-tracker` の対応PRを反映する。写真export・手動代表指定の代替選定・スナップショット生成から風景を除外する。公開の蓋だけで写真充足を算出する。
3. 図鑑の日次同期と生成結果を確認する。既存の静的JSONに新条件が反映されるまでは、古い数字が表示され得る。
4. 写真館側を公開する。

初期の図鑑写真枠は蓋の写真だけを配信し、風景は写真館で閲覧する。図鑑へ風景枠を新設する変更は含めない。DB・図鑑の変更を残して写真館のコードだけ旧版へ戻すことは可能。分類済みの風景をfalseへ戻すロールバックは行わない。

## 検証

- `npm run type-check`、`npm run test:manhole-gallery`、`npm run test:prefecture-completion`、`npm run test:analytics`。
- `npm run build`：ローカル設定を値を表示せず渡して完了。
- `npm run lint` はリポジトリに設定ファイルがなく初期設定を要求するため、一時設定の `next/core-web-vitals` で変更したTS/TSXを検査（エラーなし、既存形式の警告あり）。
- 一時的なPGlite環境の最小テーブルで、マイグレーション、既定値、公開/非公開の集計、カード選定、列権限、写真INSERTを検証済み。これは全Supabaseスキーマでの検証を代替しない。
- 実際のローカルSupabase環境向けの回帰検証は `npm run verify:photo-landscape`。`tools/verify-photo-landscape.sql` が新規fixtureを挿入し、最後にROLLBACKする。公開面の既存検証 `tools/verify-app-user-visibility.sql` の列集合も更新した。
- 今回の最終差分では `npm run test:manhole-gallery` 24件と `npm run type-check`（GA4契約・公開列チェックを含む）が成功。
- ローカルUIの再確認は、基準cloneのローカルSupabaseが本migration未適用で `is_landscape` を返せなかったためデータ部分は未実施。公開後にログアウト状態で再確認する。認証付きの実投稿・R2保存の通し確認は未実施。
