# 写真の AI タグ

写真に自動のタグを出す（チップに「AI」の印は付けず、タグの下に「タグは AI で自動判定しています。間違っていたらごめんなさい。」と注釈を出す）（蓋詳細の一覧と拡大表示・トップ・人気・訪問一覧・利用者ごとの訪問一覧・写真の個別ページ）。
判定は k11 の manhole-score が毎朝の自動採点で行い、
`photo.ai_tags` に書く。アプリは判定しない。

| タグ | 判定 | 出す条件 |
|---|---|---|
| ぬいぐるみ | 学習した分類器（ResNet-50 埋め込み＋COCO 検出器など）。注釈 1836 枚で 適合 0.86 / 再現 0.77 | `ai_tags.plush = true` |
| 夜 | 撮影時刻（EXIF）と蓋の位置から求めた太陽高度が −6° 未満 | `ai_tags.night = true` |
| 風景 | シーン分類（中心・周辺・看板・風景）の風景 | `ai_tags.scene = 'landscape'` かつ投稿者が「周辺の風景」を選んでいない |
| 人物 | 公開用属性モデル | `ai_tags.person = true` |
| 雪 | 公開用属性モデル | `ai_tags.snow = true` |
| 紅葉 | 公開用属性モデル | `ai_tags.autumn = true` |
| 足元 | 公開用属性モデル | `ai_tags.feet = true` |

- 周辺（`wide_context`）は写真の半分以上に付くのでタグにしない。看板は教師が足りないので出さない
- 投稿者の「周辺の風景」（`is_landscape`）を上書きしない。代表写真・写真の充足率の計算にも使わない
- 投稿者が AI のタグを外す操作はまだ無い。外れが目立ったら上書き用の列を足す
- ログイン後の `/visits`（スタンプ帳）は対象外。丸い小さなアイコンと 7〜9px の文字だけで、「周辺の風景」バッジも出していない。
  自分の写真のタグは蓋詳細と写真の個別ページで見られる（ログイン前の `/visits` の見本タイルには出す）

## 書き込み経路

`scoring.apply_photo_scores` の各行に任意の `ai_tags` を足せる（`20261004100000_photo_ai_tags.sql`）。
中身は型から検査し、知らないキー・範囲外・500 バイト超は拒否する。関数の署名は変えていないので、
`scoring.audit_photo_scorer()` の許可リストはそのまま。利用者からの書き換えは
`photo_protect_quality_score` トリガが元に戻す。

## 公開の順番

1. マイグレーションを本番に適用する。有効な版が `quality_score/0.3.0` になり、k11 の 0.2.0 のジョブは止まる（止まるのが正しい）
2. k11 の manhole-score を 0.3.0（`ai_tags` を書く版）に切り替える。翌朝 05:15 の実行で既存の全写真に `ai_tags` が入る
3. 写真館（アプリ側）を出す。**必ず 1 の後。** アプリは `photo.ai_tags` と `public_user_visit_card.latest_photo_ai_tags` を
   select するので、列が無いうちに出すと写真の一覧・訪問一覧が 500 になる。2 の前に出るのは構わない（`ai_tags` が NULL ならタグが出ないだけ）

確認: `npm run verify:photo-scorer`（ローカル）、本番は適用後に `select count(*) from photo where ai_tags is not null`。

## 追加属性（2026-11-07、quality_score/0.12.0）

利用者の採用基準は、蓋単位の分割で学習に使わない写真から測った適合率が50%以上。
各写真のモデル出力を一律0.5で切るという意味ではない。
閾値は学習側のOOFだけで選ぶ。蓋単位で約20%を隔離し、学習にも閾値選択にも使わず適合率を評価する。
評価した同じモデルを保存し、検証側を含めた全件で学習し直さない。分割は固定seed=17の最初のfoldで、良い結果の分割を探さない。

| 属性 | 独立検証の適合率 | 再現率 | 閾値 | 検証の正例 | 予測陽性中の正解 |
|---|---:|---:|---:|---:|---:|
| 人物 | 90.9% | 90.9% | 0.43 | 11 | 10 / 11 |
| 雪 | 50.0% | 14.3% | 0.88 | 7 | 1 / 2 |
| 紅葉 | 60.0% | 60.0% | 0.26 | 5 | 3 / 5 |
| 足元 | 74.5% | 68.6% | 0.51 | 51 | 35 / 47 |

雪・紅葉は特に検証件数が少なく、50%以上という実測値は本番精度の保証ではない。
前のOOFと同じデータで閾値を選んだ数値（98%など）は公開精度の根拠には使わない。

桜は教師不足、雨・影・反射は現行評価で適合率50%未満のため追加しない。
切れは品質管理用のままとし、写真を探す公開タグには加えない。
既存のぬいぐるみ・シーンと代表写真の採点モデルは切り替えない。

K11の `scripts/public_attrs.py` が既存の `attr_models.py` の学習・特徴量を再利用する。
`models/public_attrs_v2.pkl` と評価の `models/public_attrs_v2.json` を固定し、
新着も同じ特徴量（埋め込み・手作り・人物検出・時刻・蓋の枠）で推論する。
`attrs_model: 'public_attrs/2'` と4属性の真偽を書き込む。学習時と読み込み時は同じ `validate_report` を使い、NaN・欠損・閾値範囲外も拒否する。
学習時に基準未達の属性は明示的に除外・記録し、採用がゼロならモデルを保存しない。読み込み時の不正なモデルはジョブを止める。
確認画面用の `data/attr_models_latest.json` を更新しても本番モデルは変わらない。
モデル作成後の再実行は既存モデルを上書きしない。更新は別の版として評価し直す。

### 表示範囲と入力契約

- 人物・足元は通常サイズのタグに表示する。`compact`（訪問見本・利用者の訪問タイル）では省き、季節タグと既存タグを残す。
  注釈の表示判定も同じcompact設定を使う。ぬいぐるみ特集の読み上げラベルもcompactに揃える。
- 公開属性が1つでもあれば `attrs_model` は必須。旧タグだけの写真は従来どおり受け付ける。
- 推論は埋め込みを写真IDで引き、欠落・重複・余分なIDは書く前に拒否する。
  枠なしは学習側 `Features.row` と同じ `[0.0] * 5`。順序変更と枠欠損も検証する。
- 書き込み前に枠を小数4桁、ぬいぐるみ確率を3桁、代表写真の点を既存どおり4桁に統一する。
  NumPyの真偽・数値スカラーはPython標準型に変換する。`tag_payload.py` は標準ライブラリだけを使う。
  空白を含めたUTF-8で500バイトを検査し、超過・NaN・不正な型の写真だけをスキップする。
  未採点のまま残し、バッチ記録と状態の `tag_payload_errors` にID・理由を記録する。
  他の正常な写真は書き込み、スキップがあれば結果を `partial` にする。

### 反映順

1. K11の `pokefuta-score.timer` を `systemctl --user stop pokefuta-score.timer` で止める。
   `systemctl --user is-active pokefuta-score.service` で既存ジョブが完了していることを確認する。
   DBの版が変わる途中で0.11.0のジョブを起動しない。進行中のジョブは強制終了せず完了を待つ。
2. K11変更を取り込む前に `scripts/public_attrs.py --train` で公開用モデルを作る。
   すでに固定済みなら再学習せず、同梱JSONの成績と版を確認する。
   DB変更前に新しいコードの隔離worktreeで `SceneAttrs()`・`RepScorer().self_check()` を読み込み、
   モデルの存在・破損・公開条件を検査する。失敗したらDBを切り替えず、先にモデルを修復する。
3. 本番へ `20261107130000_photo_ai_tags_attributes.sql` を適用。
4. K11に対応する変更を取り込み、ジョブを `quality_score/0.12.0` に切り替える。
   全件再採点のため、通常の `pokefuta-score.service` を実行する。
5. 書き込み成功・4属性の件数・代表写真の点の欠落が無いことを確認する。
6. 手動ジョブの完了と版・残件・`tag_payload_errors` を確認してから
   `systemctl --user start pokefuta-score.timer` で再開する。起動検証や手動実行が失敗したら再開せず修復する。
7. 写真館の表示変更をデプロイする。未採点写真や旧タグだけの写真にも後方互換がある。

K11の変更は [引き継ぎ](inbox/2026-11-07-photo-ai-tags.md) と同梱パッチを参照。
DBの関数署名・権限・500バイト上限・楽観ロックは維持する。利用者からの書き換えは許可しない。

### 2026-11-08 レビューで確認した判断

- 採用条件は利用者指定の「独立検証の適合率50%以上」という点推定を維持する。
  検証の予測陽性10件や信頼区間下限50%は別の条件になるため、今回の追加条件にはしない。
  雪1/2・紅葉3/5は少数検証であり、本番精度を保証するものとは扱わない。
- 公開モデルの欠落・破損は起動時に全体を止める。公開属性なしで0.12.0採点済みにすると、
  モデル修復後に未採点の検索から拾えなくなるため、自動でタグを外して続行しない。
  状態の `stage` は `permission_audit` / `model_validation` / `batch` を分けて記録する。
- `A.box_features` はrecs中の枠ではなく `data/manhole_boxes_lid.json` を写真IDで引く。
  学習と推論は同じ保存枠を使う。`crop.tags` の前でも枠ありの特徴の末尾は1になる。
- 学習の `features.src` はバックアップ時点の全写真の特徴量キャッシュで、写真の種類のフィルターではない。
  推論をその写真ID一覧に制限すると、新着写真がすべて対象外になるため制限しない。
  学習と同じ特徴量を計算できる新着を対象とし、精度は評価したバックアップの検証値として扱う。

## 雪景色の特集

`/photos/snow` は `ai_tags.snow = true` の公開写真を新しい投稿順に最大300枚表示する。
トップの特集カードは `/api/features/snow` から同じ集合の枚数と先頭3枚を取得し、
0枚または取得できない場合は非表示。ページ・APIの再検証は600秒。
写真全体を表示し、AIの自動判定であることを明記する。
取得は既存のぬいぐるみ特集と共有し、anon権限・公開訪問の条件・公開名RPCを維持する。
